# Protein Docker — мобильная вёрстка, производительность, двуязычность (RU/EN)

**Дата:** 2026-08-05
**Статус:** утверждён

## 1. Задача

Три независимые цели в одном проекте:

1. **Мобильная вёрстка.** Сейчас на экране 390px шесть `position:fixed` панелей наезжают друг
   на друга, а тач-управление молекулой отсутствует физически — игра на телефоне непроходима.
2. **Производительность на телефоне.** Игра «подвисает» при вращении структуры.
3. **Двуязычность.** Добавить английский, кнопку выбора языка с двумя опциями (Русский /
   English). Язык при первом заходе — по языку браузера, всё кроме русского → английский.

## 2. Диагностика (основание для решений)

Разбор текущего кода перед проектированием:

- **Тач-обработчиков нет вообще.** `js/controls.js` слушает только `mousedown` / `mousemove` /
  `mouseup` / `wheel` / `keydown`. На телефоне работает лишь орбита и пинч камеры силами самого
  3Dmol (библиотека маппит `touchstart`/`touchmove`/`touchend` на свои mouse-хендлеры). Молекулу-
  лекарство пальцем нельзя ни сдвинуть, ни повернуть, ни утопить по глубине.

- **Причина подвисаний при вращении.** Флаг `camInteracting` (`js/state.js:50`) выставляется
  только внутри mouse-хендлеров `controls.js`. Цикл `animate()` (`js/scene.js:293`) пропускает
  перерисовку геймплея, пока камера в работе, — но на тач-устройстве флаг **никогда** не
  становится `true`. Итог: каждые 45 мс `draw()` вызывает `removeAllShapes()`, заново создаёт
  ~20 сфер и цилиндров (новая геометрия → выгрузка в GPU) и делает второй `viewer.render()`
  поверх того, который 3Dmol уже выполнил для поворота. Это и есть наблюдаемый симптом.

- **Дополнительные множители нагрузки:**
  - DPR устройства: 3Dmol жёстко читает `window.devicePixelRatio` внутри `Renderer.setSize`,
    конфигурационной опции нет. На телефоне с DPR 3 это ~3 млн пикселей на кадр.
  - `cartoonQuality` по умолчанию 10 (опция поддерживается `createViewer`).
  - Полупрозрачная VDW-поверхность на **весь** белок (`js/scene.js:135`) — самый дорогой
    элемент по fill-rate, а прозрачность его удваивает.
  - `anchorFor()` (`js/controls.js:44`) проецирует **все** атомы белка (тысячи) на каждое
    событие зума.
  - `study.js:255` проецирует `hoverAtoms` на каждый `mousemove` без троттлинга.

- **Объём перевода:** ~250–300 пользовательских строк. Кириллические фрагменты по файлам:
  `tutorial.js` 135, `levels-data.js` 85, `coach.js` 79, `index.html` 69, `study.js` 46,
  `hud.js` 43, `scoring.js` 26, `levels.js` 22, `scene.js` 20 (часть — комментарии).

**Вывод по цели №2: приложение не тяжёлое по природе.** Это набор конкретных дефектов, главный
из которых — три строки кода.

## 3. Архитектура

Проект — классические `<script>` в одном глобальном скоупе; порядок загрузки в `index.html`
несущий. Новые файлы встраиваются в цепочку зависимостей:

| Файл | Ответственность | Место в цепочке |
|---|---|---|
| `js/lang-en.js`, `js/lang-ru.js` | плоские словари `I18N_EN` / `I18N_RU` | сразу после `state.js` |
| `js/i18n.js` | рантайм: `LANG`, `t(key,vars)`, `setLang()`, `applyI18n()`, `numFmt()` | после словарей, до всех модулей с текстом |
| `js/perf.js` | `IS_TOUCH`, `QUALITY`, `applyQualityProfile()`, кап DPR | до `scene.js`; кап DPR применяется на самой загрузке файла, т.е. заведомо раньше `createViewer()` внутри `init()` (вызывается из `main.js`, последним) |
| `css/mobile.css` | всё мобильное в одном месте | вторым `<link>` после `styles.css` |

Тач-ввод — **не** отдельным файлом, а рядом с mouse-кодом в `controls.js`: иначе продублируется
вся математика перемещения, трекбола и coach-магнита. Вместо дублирования из `mousemove`
выносятся три чистые функции, которыми пользуются обе ветки ввода:

- `ligMove(dx, dy)` — перемещение в плоскости экрана (`camBasis().right`/`.up`, `pxPerA()`),
  включая coach-магнит (притягивание центроида к треку).
- `ligRotate(dx, dy)` — экранный трекбол (`axisAngleMat` вокруг `b.up` и `b.right`).
- `ligDepth(dy)` — сдвиг вдоль `camBasis().fwd`.

**Отвергнутые варианты i18n:** дублирование HTML-блоков на двух языках (гарантированно
разъедется), отдельные страницы `index.html` / `index.ru.html` (дублирование + ломает единый
прогресс в localStorage и внешние ссылки).

## 4. Мобильная вёрстка

Порог: `@media (max-width: 820px), (pointer: coarse)`. Целевая раскладка:

```
┌──────────────────────────────────────┐
│ PD · KRAS G12C          🔇 🌐 ☰      │  хедер: мишень в одну строку, эллипсис
│ СЧЁТ 8 400 · РЕКОРД 9 100            │  #score схлопнут в хедер
│                                      │
│           🧬  3D сцена               │
│                🔹                    │
│                                      │
│ ✋ ДВИГАТЬ │ 🔄 ВРАЩАТЬ │ ↕ ГЛУБИНА  │  segmented control режимов
│ КОНТАКТ С КАРМАНОМ        ПЛОТНО     │  #meter, компактный
│ ▓▓▓▓▓▓▓▓▓▓▓▓░░░░░░  до цели: 3.1 Å  │
│ ┌────────────────────────────────┐   │
│ │      ▶ ТЕСТ ЛЕКАРСТВА          │   │  главное действие всегда видно
│ └────────────────────────────────┘   │
└──────────────────────────────────────┘   + env(safe-area-inset-bottom)
```

Решения:

- **`#actions`** (7 кнопок в столбик) → bottom-sheet, открывается кнопкой **☰** в хедере.
  Кнопка «▶ ТЕСТ ЛЕКАРСТВА» вынесена из шита и постоянно видна под метром — это главное действие.
- **`#score`** схлопывается в строку хедера (`СЧЁТ N · РЕКОРД M`), сама панель скрыта.
- **`#help`** (подсказки по мыши) скрыт: на тач-устройстве его текст просто неверен.
  Тач-инструкция уходит в «ОБ ИГРЕ → КАК ИГРАТЬ» и в одну строку над переключателем режимов.
- **`#lb`** (лидеры) скрыт как панель, открывается пунктом «🏆 ЛИДЕРЫ» из шита в виде модалки
  (переиспользуется существующая разметка `#lb`, меняется только позиционирование).
- **Модалки** (`#tutCard`, `#levelsCard`, `#coachDoneCard`): ширина `calc(100vw - 12px)`,
  `max-height: 88vh` со скроллом, `#levelGrid` в одну колонку, все тапабельные зоны ≥44px
  (сейчас `#tutSkip` и `#levelsClose` — 12–16px текст).
- **`#tip`** (режим «ИЗУЧЕНИЕ»): не у курсора, а плашкой на всю ширину внизу экрана.
- **Ландшафт** (`max-height: 500px`): метр сжимается до одной строки, `#mission` скрывается.
- **Safe area:** `padding-bottom: env(safe-area-inset-bottom)` на нижних панелях (вырез и
  home-bar iPhone).

## 5. Тач-управление

Схема — переключатель режимов (выбрана как единственная без конфликта жестов и понятная новичку):

- Хит-радиус молекулы: 34px → **48px** для пальца (константа в `ligHit`).
- **Один палец, старт по молекуле** → активный режим: `move` (по умолчанию) / `rotate` / `depth`.
  Режим переключается segmented control'ом над метром.
- **Один палец по фону** → орбита камеры силами 3Dmol, не перехватываем.
- **Два пальца** → зум/сдвиг силами 3Dmol.
- В обоих последних случаях выставляется `camInteracting` (см. §6).
- `touch-action: none` на `#viewer` — иначе страница скроллится и срабатывает double-tap-zoom.
- **Coach на тач:** шаг 3 «схвати мышью» → «проведи пальцем по дорожке»; шаг 4 «правый клик +
  мышь» → «переключись на 🔄 ВРАЩАТЬ». Реализуется парами i18n-ключей `.mouse` / `.touch`,
  выбор по `IS_TOUCH`. Блинкующий курсор `#coachCursor` («схвати и веди») меняет подпись
  аналогично.
- **Режим «ИЗУЧЕНИЕ»** на тач работает по тапу вместо hover.

Клавиатурное управление и мышь на десктопе не меняются.

## 6. Производительность

Реализуется как профиль `QUALITY ∈ {auto, low, high}`. `auto` = `low` при `pointer: coarse`,
иначе `high`. Переключатель «Графика: авто / лёгкая / красивая» — в bottom-sheet (мобильный) и
в меню действий (десктоп); значение в `pd_quality`.

| # | Правка | Профиль |
|---|---|---|
| 1 | `camInteracting = true/false` на `touchstart` / `touchend` / `touchcancel` | всегда |
| 2 | **Dirty-render** (см. уточнение ниже): пропускается пересборка шейпов и `viewer.render()`, а не расчёт | всегда |
| 3 | Кап DPR до 1.5 через `Object.defineProperty(window, 'devicePixelRatio', {get})` **до** `createViewer` | low |
| 4 | `createViewer(..., {cartoonQuality: 3, antialias: false})` | low |
| 5 | VDW-поверхность только для остатков в ~16 Å от кармана (набор `resi` собирается из той же выборки, что `buildPocketAtoms()`) | low |
| 6 | Анимации (пульс кармана, мигание ghost) на 12 fps вместо 20; маркер кармана статичен, когда игрок не касается экрана | low |
| 7 | `anchorFor()` — субсэмплинг атомов (каждый 8-й) вместо проекции всех | всегда |
| 8 | Hover-проекция в `study.js` — троттл 60 мс | всегда |

**Уточнение к #2 (что именно считается «грязным»).** Дорогая часть кадра — это
`removeAllShapes()` + ~20 вызовов `addSphere`/`addCylinder` + `viewer.render()`. Дешёвая часть —
`minDistance()`, `fitEnergy()`, `quality()` и обновление текста HUD. Поэтому цикл каждый тик
по-прежнему выполняет расчёт и обновляет HUD (это сохраняет текущее поведение шкалы, звука и
coach-автоперехода), но пересборку шейпов и `render()` делает только если выполнено хотя бы одно
условие:

- изменились `lig.x/y/z/rx/ry/rz` относительно предыдущего кадра;
- активна анимация: пульс маркера кармана, мигание solution-ghost (`showSolution`), coach-трек,
  `coachBlinkDrug`;
- изменилось состояние видимости (`coachHidePocket` / `coachHideDrug` / `showSolution`) или
  пересёк границу кармана флаг `inPocket` (меняет подсветку молекулы).

На «лёгком» профиле пульс маркера отключается в покое (см. #6), поэтому при неподвижной молекуле
и выключенной подсказке ни одно условие не выполняется и рендеров нет вообще.

Осознанные визуальные следствия «лёгкого» профиля (утверждены):

- **#5:** белок на телефоне выглядит лентами с подсвеченным карманом, а не облеплен
  полупрозрачной поверхностью целиком. Вид другой, читаемость цели лучше.
- **#6:** пульсация зелёного маркера замирает, пока игрок не касается экрана. Именно это даёт
  0 рендеров в покое.

Требуют проверки на живом устройстве, а не по документации:

- **#3** — у 3Dmol нет API для DPR (`setPixelRatio` в сборке отсутствует, `Renderer.setSize`
  читает `window.devicePixelRatio` напрямую), поэтому используется перехват геттера. Если не
  сработает — fallback: рендер в canvas меньшего размера с CSS-масштабированием до 100%.
- **#5** — форма селектора 3Dmol для выборки по набору остатков проверяется на реальном
  вызове `addSurface`.

## 7. Двуязычность (i18n)

- **Ключи:** `hud.test`, `meter.contact`, `about.2.title`, `levels.p53.blurb`,
  `hotspot.p53.175`, `coach.step3.touch`.
- **`t(key, vars)`** с подстановкой `{{name}}`. Отсутствующий ключ возвращает сам ключ и пишет
  `console.warn` — дырка в переводе видна сразу.
- **Статика в HTML:** атрибуты `data-i18n` (в `textContent`), `data-i18n-html` (в `innerHTML`,
  для строк с разметкой), `data-i18n-title` (тултипы кнопок).
- **Числа:** `numFmt(n)` вместо жёстких `toLocaleString('ru-RU')` (5 мест в `hud.js`).
- **`levels-data.js` чистится от текста.** Остаются только `id`, `pdb`, `open`,
  `pocket.type`/`pocket.value`. Поля `name`, `sub`, `blurb`, `drug`, `pocket.label` и таблица
  `hotspots` уезжают в словари под ключами `levels.<id>.*` и `hotspot.<id>.<resi>`. `name` тоже
  локализуется: «RAS (дикий тип)» → «RAS (wild type)».
- **Переключение на живую**, без перезагрузки страницы и без повторной загрузки PDB:
  `setLang()` → запись `pd_lang` → `applyI18n()` → перерендер открытых модалок (`renderTut()`,
  `renderLevels()`) → `resetLabels()` и перерисовка 3D-меток (`◎ ЦЕЛЬ`, `🔹 ТВОЁ ЛЕКАРСТВО`) →
  обновление `#hdrSub`, `#mission`, лидерборда, `document.title`, атрибута `<html lang>`.
- **Кнопка 🌐** в хедере рядом с 🔇, дропдаун с двумя опциями `English` / `Русский`, галочка у
  активного.

**Определение языка при первом заходе:**

```js
// pd_lang → выбор игрока (приоритет). Пусто → язык браузера, всё кроме ru → en.
function detectLang(){
  const saved = localStorage.getItem('pd_lang');
  if(saved === 'ru' || saved === 'en') return saved;
  const nav = (navigator.languages && navigator.languages[0]) || navigator.language || '';
  return /^ru\b/i.test(nav) ? 'ru' : 'en';
}
```

Префикс `ru` покрывает `ru`, `ru-RU`, `ru-BY`; всё остальное, включая пустое и `undefined`, даёт
английский. Явный выбор в дропдауне записывается в `pd_lang` и с этого момента перебивает браузер.

## 8. Порядок работ

Три этапа, каждый проверяется самостоятельно. i18n — последним, когда набор строк устоялся после
мобильных правок (иначе новые мобильные строки придётся доперводить):

1. **Производительность** — маленький изолированный этап, сразу снимает основную боль.
2. **Мобильная вёрстка + тач-управление.**
3. **i18n-каркас + полный перевод EN/RU.**

## 9. Верификация

Автотестов в проекте нет (нет ни сборки, ни тест-раннера, ни package.json). Проверка:

- **Вёрстка и жесты:** Chrome DevTools device emulation, 390×844 и 360×640, 4× CPU throttle;
  портрет и ландшафт; все модалки; полное прохождение coach на тач.
- **i18n:** самопроверка `?i18ncheck` — сверяет, что все ключи из `data-i18n*` и все вызовы
  `t()` присутствуют в **обоих** словарях, и что на экране нет «сырых» ключей.
- **Уровни:** все 6 уровней загружаются, карман находится, метки корректны в обоих языках.
- **FPS на реальном телефоне подтверждает пользователь** — эмулятор не воспроизводит GPU
  fill-rate, а именно он здесь узкое место. Результат сообщается фактически, без утверждений
  «стало быстро» без подтверждения.
